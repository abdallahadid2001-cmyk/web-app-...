# نظام مبيعات ومخزون وورديات للمحلات الصغيرة

## المعمارية المقترحة

- الواجهة: TanStack Start + React + Tailwind، عربية RTL بالكامل، Mobile-first وأزرار كبيرة.
- الخادم وقاعدة البيانات: Lovable Cloud (PostgreSQL + مصادقة + صلاحيات على مستوى الصفوف).
- كل العمليات الحساسة (إتمام بيع، إغلاق وردية، تعديل مخزون) تتم عبر دوال داخل قاعدة البيانات لتكون عملية واحدة غير قابلة للتجزئة.
- لا بيانات وهمية، ولا ذكاء اصطناعي، ولا حذف لأي سجل.

## الجداول

| الجدول | الغرض |
| --- | --- |
| profiles | بيانات المستخدم (الاسم، الحالة) |
| user_roles | الدور: owner أو seller (جدول منفصل لمنع رفع الصلاحيات) |
| categories | تصنيفات المنتجات |
| products | الاسم، الباركود، التصنيف، سعر البيع، سعر التكلفة، الرصيد، حد التنبيه، مفعّل |
| shifts | البائع، وقت الفتح/الإغلاق، النقدية الافتتاحية، المتوقعة، الفعلية، الفرق، الحالة |
| sales | الوردية، البائع، الإجمالي، طريقة الدفع، النوع (بيع/مرتجع)، الوقت |
| sale_items | البيع، المنتج، الكمية، سعر البيع وقت العملية، تكلفة الوحدة وقت العملية |
| stock_movements | المنتج، الكمية، نوع الحركة (شراء/بيع/مرتجع/تسوية/هالك)، المرجع، المستخدم، الوقت |
| purchases + purchase_items | المشتريات الواردة وتكلفتها |
| audit_log | المستخدم، الإجراء، الكيان، المعرّف، الوقت، التفاصيل (قديم/جديد/السبب) |

### العلاقات
مستخدم ← ورديات ← مبيعات ← بنود بيع ← منتجات. كل بند بيع ينتج حركة مخزون. كل مشترى ينتج حركة مخزون. كل عملية حساسة تكتب سطرًا في سجل العمليات.

## قواعد العمل

- وردية مفتوحة واحدة فقط لكل بائع.
- لا بيع بدون وردية مفتوحة.
- رصيد المخزون لا يتغير أبدًا بدون حركة مخزون مسجلة.
- تُحفظ تكلفة الوحدة داخل بند البيع لحساب الربح لاحقًا بدقة.
- الربح الإجمالي = الإيراد − تكلفة البضاعة المباعة.
- النقدية المتوقعة = الافتتاحية + مبيعات الكاش − مرتجعات الكاش.
- الفرق = الفعلية − المتوقعة (سالب عجز، موجب زيادة).
- بعد الإغلاق تصبح الوردية غير قابلة للتعديل إلا من المالك مع تسجيل السبب في السجل.
- لا حذف لأي بيع أو حركة أو سجل.

## الصلاحيات

- المالك: كل شيء — المنتجات، الأسعار، المخزون، المشتريات، البائعون، كل الورديات والمبيعات، التقارير، التعديلات الإدارية، السجل.
- البائع: دخول، بدء وردية، بيع، مرتجع وفق القواعد، عرض ورديته الحالية فقط، إغلاق ورديته.
- كل ذلك مفروض من قاعدة البيانات نفسها، وليس بإخفاء أزرار فقط.

## ترتيب التنفيذ

1. تفعيل الخادم وقاعدة البيانات + الجداول + الصلاحيات + تسجيل الدخول والأدوار.
2. إدارة المنتجات والتصنيفات والمخزون (للمالك) + إنشاء البائعين.
3. الورديات: بدء وردية بنقدية افتتاحية.
4. شاشة البيع السريعة: شبكة منتجات، بحث، سلة، طريقة دفع، إتمام بيع بعملية واحدة تخصم المخزون.
5. إغلاق الوردية والتسوية النقدية.
6. لوحة المالك اليومية.
7. المشتريات + المرتجعات + التقارير الأربعة + سجل العمليات.

بعد كل مرحلة أتأكد أن المسار السابق ما زال يعمل.
